## P0 — 핵심 문제

1. 학급 변경 후 시간표가 바뀌지 않는 현상 — 사용자 제보, 원인 미확정.
2. 고등학교에 4~6학년이 표시됨 — 학교급과 관계없이 1~6학년 고정.
3. 교사별 시간표가 주간 시간표가 아님 — 현재 단순 수업 검색 목록.
4. 모바일 UI가 지나치게 큼 — 시간표까지 내려가는 데 스크롤이 많음.
5. 모바일 주간 시간표의 가로 스크롤 — 최소 너비 550px.
6. 프록시 환경에서 IP별 요청 제한 오작동 가능성 — 서로 다른 사용자가 하나의 IP로 인식될 위험.
7. 서버 전체 차단 기능의 오탐 가능성 — 정상적인 요청 집중에도 503이 발생할 수 있음.
8. 실제 브라우저 E2E 테스트 부재 — CI가 통과해도 화면 오류를 발견하기 어려움.

## P1 — 기능 정확성·안정성 문제

9. 학교 변경 후 이전 학년·반 설정이 유지될 수 있음.
10. 존재하지 않는 학년·반을 선택할 수 있음.
11. 동명이인 교사 구분이 어려움.
12. 교사 검색에서 일부 이름만 일치해도 결과가 섞일 수 있음.
13. 주말 시간표 처리 불일치 — 백엔드는 토·일 데이터를 제외하지만 프런트엔드에는 주말 표시 로직이 존재.
14. 시간표 변경 이력의 `null` 교사 값 처리 문제 — 특정 입력에서 SQLite 저장 실패 가능.
15. 변경 이력이 모든 시간표 변경을 기록하지는 못함 — 실제 관측 시점 사이의 변경은 누락 가능.
16. 원본 응답이 비정상적으로 불완전할 때 데이터 정확성 검증 부족 가능성.
17. 캐시 갱신 중 오래된 응답이 표시될 위험 — 일부 방어 로직은 존재하며 추가 검증 필요.
18. 캘린더 구독 시 교시마다 종일 일정이 생성됨 — 하루에 여러 종일 일정이 쌓임.
19. 캘린더 구독 URL의 잦은 재조회 가능성 — 구독 클라이언트에 따라 서버 요청이 증가할 수 있음.
20. 캘린더 구독에 실제 수업 시작·종료 시각이 없음.
21. 급식 학교 자동 매칭의 예외 상황 — 동명이교·지역 정보 불일치 시 정확성 검증 필요.
22. 서버 오류 메시지가 포괄적임 — CORS·네트워크·원본 서버 오류를 사용자가 구별하기 어려움.
23. 모바일에서 공유·구독·즐겨찾기가 시간표보다 위에 배치됨 — 새 기능이 늘수록 첫 화면이 길어짐.
24. 학년 전체 비교 화면의 모바일 사용성 부족 — 반이 많은 학교에서는 가로 스크롤 부담.
25. 이용 통계 기본 활성화 정책 — 별도로 끄지 않으면 가명 방문 통계가 수집됨.

## P2 — 품질·유지보수 문제

26. `App.svelte`에 기능과 상태 관리가 집중됨 — 코드가 복잡해져 회귀 오류 위험 증가.
27. 프런트엔드 CSS의 높은 복잡도 — 화면 크기별 레이아웃 유지보수가 어려움.
28. 실제 모바일 브라우저 호환성 검증 부족 — iOS Safari·Android Chrome 확인 필요.
29. API 문서와 신규 기능 간 불일치 가능성 — iCalendar·필터 API 등 포함.
30. HTTP 캐시 최적화 부족 — API에 `Cache-Control: no-store` 적용.
31. 조건부 요청 지원 부족 — `ETag`·`If-None-Match` 활용 없음.
32. 시간표 전체 데이터를 전달하는 방식의 비효율 — 특정 반만 필요한 경우에도 프런트엔드는 학교 전체 데이터를 요청.
33. API Playground 기능 범위 부족 — 신규 필터·캘린더 구독 기능을 모두 직접 체험하기 어려움.
34. 분석 데이터 일부 누락 가능성 — 비동기 기록 큐가 가득 차거나 서버가 종료되는 경우.
35. 가명 방문자 수와 실제 이용자 수의 차이 — 브라우저·저장소 기준 집계.
36. Parser health 검증 범위가 좁음 — 학교 검색은 검사하지만 시간표 전체 파싱은 확인하지 않음.
37. 원본 서버 장애와 서비스 자체 장애를 구별하는 모니터링 부족.
38. 집 Wi-Fi·정전·공유기 장애에 따른 가용성 문제.
39. 공개 API의 운영 정책·재제공 범위 검증 미완료.
40. 라이선스 파일 부재 — 외부 개발자의 코드 재사용 조건이 명확하지 않음.
