# 집 Wi-Fi 사용자 테스트: 2026-11-13

사용자가 내부 검수 사이트에서 학교 검색, 주간 이동, 급식 선택과 새로고침을 수행했다. 측정 구간은 23:55:56~23:56:25 KST이며, 검수 서비스는 직전에 재시작되어 캐시가 비어 있었다. 근거는 파이의 `opensigan-preview.service` journal에 기록한 `timing` 행이다.

| 요청 | 관측 수 | 서버 처리 시간 |
|---|---:|---|
| 시간표 학교 검색 | 1 | 141.84 ms |
| 캐시가 없는 시간표 조회 | 2 | 144.49, 149.86 ms |
| 캐시된 시간표 조회 | 8 | 5.40~5.95 ms |
| NEIS 학교 검색 | 1 | 97.76 ms |
| 급식 첫 조회 | 1 | 95.41 ms |
| 캐시된 급식 조회 | 1 | 0.35 ms |
| HTML 재검증 (304) | 1 | 0.32 ms |

값은 GET 처리 시작부터 응답 헤더 생성까지의 경과 시간이다. 원본 API 대기와 서버의 파싱·캐시 처리는 포함하고, 클라이언트와의 통신, 응답 본문 전송, 검색 입력의 250ms 대기, 브라우저 렌더링은 제외한다. 샘플 수가 적으므로 운영 지연시간의 백분위나 서비스 수준을 나타내지는 않는다.

계측은 `deploy/lan_preview.py`에 있으며 응답의 `Server-Timing: app;dur=...` 헤더와 journal에 같은 단위(ms)로 기록한다. 계측 로그에는 검색어·학교 식별자 등 쿼리 문자열을 넣지 않는다.
