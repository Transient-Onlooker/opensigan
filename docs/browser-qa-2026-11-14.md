# 2026-11-14 실사용 브라우저 QA 결과

> 대상: https://opencigan.mcv.kr/ · 외부 브라우저 에이전트가 2026-11-14 20:44~21:00 KST에 두 차례 직접 사용하여 작성한 제보를 정리함. **P0 0건, P1 4건, P2 6건, P3 5건**(최초 분류). 아래 관측 내용은 제보 기준이며, 코드 대조로 확인한 설명은 별도로 구분한다. 실제 서비스 배포본이 최신 `main`과 일치하는지는 별도 확인 대상이다.
>
> 환경: 약 1919~1920px 데스크톱 브라우저, 보인고등학교·경기고등학교·신사중학교, 여러 학년·반, 2026-11-09~13 및 11-16~20 시간표, 2026-10-01~11-30 급식 날짜 이동. 원본 스크린샷 및 개발자 도구 콘솔/네트워크 로그는 확보되지 않음. **모바일 390px 테스트는 미수행**.

## P1 — 정확성과 신뢰

### QA-P1-1. 급식 날짜 입력 시 연도·날짜·식단 상태 불일치
- **재현:** 날짜 입력에 `20261225`를 연속 입력할 때 `0005-11-13`이 선택되고 화면 제목이 "11월 13일 일요일"로 나오는 경우. `2026-02-30` 같은 무효 입력에서는 입력 컨트롤이 invalid인 채 화면에는 "2월 3일 화요일" 및 이전/다른 식단이 함께 보임. `2026-04-31` 편집에서도 `0004-03-01` 사례 제보.
- **문제:** 키보드 날짜 세그먼트 입력 도중 브라우저가 생성한 이상 연도 또는 유효하지 않은 날짜가 화면 상태와 어긋남. **서기 5년 11월 13일의 일요일 계산 자체가 잘못됐다는 뜻은 아님**; 사용자 의도 연도와 다른 날짜를 연도를 생략한 제목으로 보여 주는 점이 핵심.
- **개선:** 유효한 실존 달력 날짜만 적용하고, 편집 도중의 임시 상태/마지막 성공 조회 결과를 구분해 표시.

### QA-P1-2. 조작·오류가 포함된 학교 공유 링크가 저장 상태까지 변경
- **재현:** URL 해시에서 학교를 `99999999:없는학교…`처럼 존재하지 않는 값으로 바꾸고 새로고침하면 학교명 및 시간표 503이 표시되고, 이후 기본 주소를 새 탭으로 열어도 같은 학교가 저장되어 있음. 해시만 바꾸고 새로고침하지 않을 때는 화면 변화 없음.
- **문제:** `readSharedClass()`는 공유값의 문자열 형식만 확인하고, `chooseSchool()`은 실제 학교 확인 전에 `localStorage`에 저장하는 구조.
- **개선:** 외부 공유값과 저장값의 학교 실재성/학년/반 정합성을 확인하고, 무효 링크에서 유효한 이전 선택을 오염시키지 않도록 처리. 서버가 503을 응답하는 원인도 구분.

### QA-P1-3. 초등학교 검색 미지원 범위에 대한 안내 부족
- **재현:** "초등학교", "초등", "개포초등학교" 검색이 모두 결과 0건이지만 중·고등학교는 정상 검색.
- **문제:** 첫 화면 문구가 모든 학교를 지원하는 것처럼 읽힘. **초등학교 지원 자체가 결함이라고 확정하지 않음**; 지원 범위를 고지하지 않는 것은 UX 문제.
- **개선:** 현재 컴시간 기반 서비스의 실제 학교급 지원 범위를 명확하게 안내.

### QA-P1-4. 일부 학교의 평일 시간표 공백 사유를 알 수 없음
- **재현:** 보인고등학교 2학년 11반 및 경기고등학교 1학년 1반의 2026-11-09~13 시간표가 월·화만 차 있고 수~금이 모두 `—`/수업 없음. 같은 주 급식은 수~금 존재하고, 다음 주 시간표는 차 있으며, 신사중학교 같은 주에는 월~금 존재. 보고된 원본 갱신 표시는 보인고 11/13 14:10, 경기고 11/13 08:14.
- **문제:** 실제 휴업, 원본 데이터 미제공, 부분 파싱 누락을 일반 공강과 구별할 수 없음. **원인은 미확정**. 급식이 있다고 수업이 반드시 있다는 뜻도 아님.
- **개선:** 원본 응답과 교차 대조하여 데이터 완전성/사유를 구분하고, 확인되지 않은 상태를 '휴업' 등으로 단정하지 않는 표시.

## P2 — 기능 상태·내비게이션·오류 안내

### QA-P2-1. 잘못된 반 입력 중 입력창과 실제 선택 학급이 어긋남
- **재현:** 반 입력에 `99` 또는 `999`를 입력하면 입력에는 그 숫자가 남지만, 상단·빠른 전환은 이전 `9반`을 유지하고 시간표에는 "1~99 사이의 반을 입력해 주세요"류 오류가 보임.
- **코드 대조:** 범위 1~99 조건 외에도 실제 `availableClasses`에 존재하지 않으면 거절하기 때문에 **99가 항상 유효한 반은 아님**. 그러나 입력값과 사용 중인 학급의 불일치 및 오류 문구는 혼란을 야기.
- **개선:** 현재 입력 중 값과 최종 선택한 학급을 명확히 구분하고 등록되지 않은 반의 오류를 정확하게 안내.

### QA-P2-2. 없는 반 공유 링크를 열면 다른 반으로 자동 전환
- **재현:** 유효한 보인고 학교 ID와 `grade=2&class=99`로 공유 링크를 열면 안내 없이 `2학년 1반` 시간표가 표시됨.
- **코드 대조:** `ensureAvailableClass()`가 유효한 반 목록의 첫 번째 항목으로 자동 변경하는 경로 존재.
- **개선:** 공유 링크의 반이 없으면 오류 또는 명시적인 변경 안내. 다른 반을 원래 요청한 반으로 착각하지 않도록 해야 함.

### QA-P2-3. 존재하지 않는 프런트엔드 경로의 기본 GitHub Pages 404
- **재현:** `https://opencigan.mcv.kr/nonexistent-page-12345` 접속 시 영문 GitHub Pages 기본 오류와 홈 링크 없음.
- **개선:** 도메인과 배포 방식을 고려해 서비스 자체의 친절한 404 안내 및 홈 이동 링크 제공.

### QA-P2-4. 긴 검색어의 400 오류가 사용자에게 불친절함
- **재현:** "보인고등학교"를 반복한 100자 검색에 "요청을 완료하지 못했어요. (400)" 표시.
- **코드 대조:** 학교 검색 API의 `q`는 최대 50자로 제한; 거절 자체는 정상. 프런트엔드가 상태코드만 표시하는 것이 개선 대상.
- **개선:** 입력 단계부터 길이 제한/안내 제공, '검색어는 최대 50자'처럼 구체적인 문구 표시.

### QA-P2-5. 앱 안에서 여러 화면을 바꿔도 뒤로가기 시 사이트 이탈
- **재현:** 학교·탭·날짜를 여러 번 변경한 뒤 브라우저 뒤로가기 1회에 이전 앱 화면 대신 직전 다른 페이지로 이탈. 앞으로 가기 시 앱 상태 복원.
- **개선:** 브라우저 뒤로가기와 앱 내부 이동의 기대 동작을 일치시키는 내비게이션/히스토리 개선.

### QA-P2-6. 시간표 탐색이 이번 주·다음 주로 제한됨
- **재현:** UI의 이전 주/다음 주 버튼이 지정 범위 밖에서 비활성화됨. API 역시 이번·다음 주만 허용.
- **해석:** **설계상 제한이며 버그 아님.** 과거/원거리 미래 조회는 원본 지원 범위를 먼저 확인해야 함.
- **개선:** 현재 지원하는 2주 범위를 화면에 안내하거나 버튼 비활성 사유를 제공.

## P3 — 추가 UX·정보 요구

### QA-P3-1. 학교 검색의 입력/결과 설명 부족
- 빈 검색어·공백·한 글자 입력은 실행되지 않지만 입력란 아래 피드백 부족. 일반 검색어 검색 결과가 10건으로 제한되어도 제한 안내 없음. 오타 "보인고등학고"는 0건만 표시. 검색 지원 범위·검색 조건·결과 제한 안내 개선.

### QA-P3-2. 즐겨찾기 0개가 되면 영역이 사라짐
- 마지막 즐겨찾기를 삭제하면 즐겨찾기 섹션이 사라짐. 빈 상태 안내 또는 진입 경로 가시성 개선.

### QA-P3-3. API 7일 범위와 여러 날짜 급식 조회의 문서 오해
- 사용자가 10~11월의 여러 날짜를 각각 조회했지만, `/api/v1/meals`가 허용하는 것은 **요청당 최대 7일**이라는 제한이므로 서로 모순되지 않음. **버그로 수정할 필요 없음**. 문구를 '한 번의 요청당 최대 7일'로 더 명확히 표현하는 개선만 선택적으로 검토.

### QA-P3-4. 비교 학년과 현재 선택 학급 동기화 혼란 / 원본 특이 문자열
- 학년 비교에서 학년을 바꾸면 상단 빠른 학급 선택도 함께 변경되므로 현재 학급을 유지한 것으로 오해 가능. 신사중 수업·교사 검색의 "스클", "이미지" 등은 원본 데이터인지 별도 대조 필요. **원본을 확인하지 않고 자동 치환하지 않음**.

### QA-P3-5. 급식 영양 정보 및 날짜 연동 기능 제안
- 급식 칼로리·영양정보 표시, 시간표와 급식에서 같은 날짜를 편하게 오가는 기능. **버그 아닌 신규 개선 아이디어**.

## 확인된 정상 동작 및 범위

- 학교 부분 검색, 여러 학교·학급 전환, 다크 모드, 교사 검색·주간 격자, 학년 비교, 시간표 새로고침 중복 클릭 방지, 주말 빈 상태, NEIS 조·중·석식과 알레르기 경고, 즐겨찾기 추가/삭제, 유효한 학급 공유 링크, 설정 JSON 백업 다운로드(약 518B), 키보드 포커스/스킵 링크가 테스트에서 대체로 정상.
- 특수 문자열 `<script>alert(1)</script>`, `' OR 1=1 --`, `<img onerror>`를 검색해도 보고된 테스트 내에서는 실행 또는 화면 붕괴 없음. **이 결과가 보안 검증 완료를 뜻하지는 않음**.
- 데스크톱 약 1920px 이외의 모바일·태블릿 동작, DevTools 콘솔/네트워크, 파일 복원 실패 상황은 미수행.

## 코드 대조 및 우선 대응 항목

- 코드 대조 시 `frontend/src/App.svelte`의 급식 날짜 검사는 정규식 + `Date.parse` 위주로 되어 있어 무효 날짜의 정규화·표시 불일치 점검 필요.
- `frontend/src/sharing.ts`의 공유 링크 학교 값은 형식 검증 위주이며 실제 존재 여부는 확인하지 않음.
- `frontend/src/App.svelte`의 `chooseSchool()`은 공유 학교의 유효성 검증 전에 저장하며, `ensureAvailableClass()`은 없는 반을 첫 번째 유효 반으로 자동 보정할 수 있음.
- 학급 입력은 `1~99` 범위 외에 등록 학급 여부도 검사해 유효한 숫자가 거부될 수 있으므로 입력과 표시의 일관성 개선이 핵심.
- 백엔드 `/api/v1/meals`의 최대 7일은 **각 API 요청의 inclusive 날짜 범위**이고, 다른 주를 추가 조회하는 행위와 충돌하지 않음.

**우선 처리 제안:** 날짜 입력의 상태 일관성 → 외부 학교/반 공유 링크 검증과 복구 → 빈 시간표 데이터 사유 검증·표시 → 반 입력 UI 일관성 → 브라우저 내비게이션·검색 오류 메시지. 기존 로드맵의 모바일 실기기 검증과 병행 가능.
