기능과 개선 과제를 우선순위별로 정리합니다. 체크된 항목은 저장소에서 구현된 기능입니다. 실기기나 운영 환경에서 더 확인할 사항은 별도로 표시합니다. [기능별 상세 목록](requests-2026-11-14.md)과 [알려진 문제](known-issues.md)도 참고하세요.

## 구현 순서와 검증

아래 작업 묶음은 위 우선순위와 연결됩니다.

1. **배치 1 (P0/P1 UI 정리 및 기본 개인화 — 완료)**: 탭 정리, 수집 시각, 교사 격자, 알레르기 경고, 고해상도 PNG, 과목/교사 표기 설정.
2. **배치 2 (P1 시간표 개인화 고도화 — 로컬 구현 완료, 기기 검증 대기)**: 학교별 교시 시작·종료 시각 입력/검증, 오늘 수업 요약, 종료/타 요일 수업 흐리기, 애니메이션 제어, 급식 가시성 설정.
3. **배치 3 (P1 설정 관리 및 P2 외부 연동 최적화 — 로컬 구현 완료, 게이트 대기)**: 학교별 설정 JSON 백업/복원/초기화, 캘린더 구독 하루 요약 모드 및 ETag/304 조건부 응답 로컬 구현.
4. **배치 4 (P0/P1 모바일 사용성)**: 좁은 화면의 시간표 행 높이와 버튼 배치를 개선했습니다. 실기기 검증은 남아 있습니다.
5. **배치 5 (P1/P2 확장 기능)**: 학급별 설정과 오프라인 시간표 조회를 구현했습니다. 모바일 PWA 검증과 개인 시간표는 후속 과제입니다.
6. **배치 6 (P0/P2 공개 서비스 전환 — 예정)**: 공개 도메인 배포, 프록시 환경 IP 제한 및 외부 구독 접근성 검증, 공개 API 운영 정책 수립.

**통과 대기 3대 검증 게이트**:
- **실제 교시 시각(bell-time) 게이트**: 학교별 교시 시각 검증 완료 후 캘린더 구독에 실제 수업 시작·종료 타임스탬프를 반영(20번).
- **공개 도메인(public-domain) 게이트**: \`opencigan.mcv.kr\` 등 실제 공개 도메인에서 캘린더 구독 및 API의 외부 네트워크 접근 가능성 검증(U02, 39번).
- **실기기(real-device) 게이트**: iOS Safari, Android Chrome, 모바일 캘린더 앱에서의 화면 렌더링 및 동기화 동작 검증(4, 5, 8, 23, 28번).

## 원칙

1. **학생용 MVP 품질을 우선**하고, 공개 API/이력 저장/알림 기능은 허용 범위·운영 안전성 검증 뒤 확장한다.
2. 기존 API 응답 계약을 유지하고 원본 서버 요청을 최소화한다.
3. 공개 API와 웹 UI는 가능하면 같은 정규화·캐시 계층을 쓴다.
4. 실제 데이터 재제공 허가·보안·변경 이력 저장과 운영 인프라 확대를 서로 독립적으로 판단한다.
5. API 문서와 구현이 충돌할 때는 테스트·실제 코드를 확인하고 문서 또는 코드를 함께 수정한다.
